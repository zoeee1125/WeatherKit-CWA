# 中央氣象署（CWA）資料源

本模組會把 iOS / iPadOS / macOS 內建「天氣」的資料切換到臺灣中央氣象署（Central Weather Administration, CWA）開放資料平台。這是本專案唯一支援的協力廠商資料源。

## 前置條件

1. 在 <https://opendata.cwa.gov.tw/> 註冊會員，並在會員中心取得授權碼（形如 `CWA-XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX`）。
2. 使用 Surge 安裝 `iRingo.WeatherKit` 模組，啟用 HTTPS 解密（MITM），並信任 Surge 憑證。
3. 請求座標必須能解析到臺灣地區的鄉鎮市區；距離最近的鄉鎮市區中心超過 50 km 時不會替換。

## 設定

在 BoxJs 開啟 `iRingo.WeatherKit`，設定以下項目：

| 設定項 | 值 | 說明 |
| --- | --- | --- |
| `[API] 中央氣象署授權碼` | 你的 CWA 授權碼 | 必填；留空時 CWA 資料源不可用 |
| `[天氣] 資料源` | `中央氣象署（臺灣）` | 預設值；替換目前天氣、逐時與每日預報 |
| `[天氣警特報] 資料源` | `中央氣象署（臺灣）` | 預設值；需要 CWA 警特報時設定 |
| `[降雨通知] 通知方式` | `天氣 App 原生優先，排程補送` | 預設值；見下方「降雨通知」 |

模組參數的鍵名分別為 `API.CWA.Token`、`Weather.Provider`、`WeatherAlerts.Provider`、`RainAlert.Mode`，效果與在 BoxJs 設定相同。

## 資料集對應

| WeatherKit 資料集 | CWA 來源 | 說明 |
| --- | --- | --- |
| `currentWeather` | `O-A0003-001` | 最近觀測站，每 10 分鐘更新 |
| `forecastHourly` | `F-D0047-093`（3 天） | 逐時預報；3 天之後用 1 週資料以 12 小時為間隔延伸 |
| `forecastDaily` | `F-D0047-093`（1 週） | 7 天，含最高/最低溫、紫外線、日出日沒、月出月沒與月相 |
| `weatherAlerts` | `W-C0033-001`、`W-C0033-003`～`010`、`W-C0034-001` | 先取縣市警報現象，再依縣市/鄉鎮覆蓋率挑選最精確的一筆 |
| `airQuality` | 環境部 `AQX_P_432` | 空氣品質指標 AQI；取最近測站，另附自建量表，見下方「空氣品質」 |
| `forecastNextHour` | `F-B0046-001`（未來 1 小時）、`O-B0045-001`（過去 1 小時） | QPESUMS 雷達定量降水格點，取周圍 3×3 最大值；每 10 分鐘更新 |

## 降雨通知

「未來一小時降水強度」通知由**天氣 App 自己**發出，不是這個模組推播的。系統讀取 `forecastNextHour` 的逐分鐘資料後自行排定通知，模組的工作只是把中央氣象署的雨量換算成 Apple 期望的結構，因此不需要代理程式在背景常駐排程。

資料裡必須存在「先無雨、後有雨」的轉折，`condition` 才會帶上 `START` 與 `FIRST_AT`，系統才有起雨時間可以排定通知。若整小時都標成「正在下雨」，系統只知道現在正在下，不會發出「即將降雨」的通知。

時間軸的欄位語意已對照 Apple 對日本、澳洲與英國座標的**真實響應**驗證過，不是憑空推測：

| 情境 | `forecastToken` | `parameters` | 該段 `endTime` |
| --- | --- | --- | --- |
| 整段有雨到底 | `CONSTANT` | `[]` | `0` |
| 有雨，之後轉晴 | `STOP` | `[{ date: 停雨時間, type: "FIRST_AT" }]` | 停雨時間（不是 0） |
| 整段無雨 | `CLEAR` | `[]` | `0` |

`summary` 也一樣：**只有最後一段**的 `endTime` 是 0（代表「一直到預報結束」），前面各段都是真實邊界。

### 讓原生通知生效的條件

1. 該城市在「天氣」App 的關注列表中（原生通知只針對列表中的城市）。
2. 在列表右上角的「通知」中開啟該城市的「未來一小時降水強度」通知。
3. 代理程式（Surge 等）與 HTTPS 解密持續運作，天氣 App 才能在背景更新資料。
4. 這場雨你還沒「主動獲知」——開過天氣 App 或看過小工具都算已知，系統會略過通知。

### 通知方式

`RainAlert.Mode` 有三種值：

| 值 | 行為 |
| --- | --- |
| `Auto`（預設） | 原生優先。天氣 App 在 15 分鐘內更新過資料時，排程腳本不補送，避免同一場雨跳出兩則通知；App 長時間沒更新（例如手機閒置）時，排程腳本才補上一則本機通知。 |
| `Weather` | 只依賴天氣 App 原生通知，排程腳本完全不動作。 |
| `Cron` | 只用排程腳本通知，與舊版行為相同。 |

排程腳本每 30 分鐘執行一次，直接查詢 QPESUMS，並有 90 分鐘冷卻時間（同一場雨只提醒一次）。

### 原生通知的已知限制

- QPESUMS 只有「未來一小時累積雨量」，沒有逐分鐘曲線，因此起雨時間以 10 分鐘近似（`ForecastNextHour.OnsetLead`）。這個近似只影響顯示與通知的起雨時間，不影響雨量總量。
- 預報窗口是**資料基準時刻 + 60 分鐘**，不是「現在 + 60 分鐘」。資料送達時基準時刻往往已經過了二十幾分鐘，窗口因此比一小時短；窗口結束之後的分鐘一律標為無雨，逐分鐘序列不會延伸到「現在 + 60 分鐘」。
- 降雨強度先按剩餘時間取比例，再攤到有雨的分鐘上。`future` 是「基準時刻起一小時」的累積量，窗口已經走掉的部分不重複計算，否則窗口只剩 36 分鐘時，0.6 毫米的整小時雨量會被放大成 1.0 毫米／小時。
- 起雨時間超過窗口終點時視為「現在就在下雨」，不會把所有雨量塞進最後一分鐘。
- 資料超過預報窗口（基準時刻已過 60 分鐘）時不再硬湊出一份預報，直接略過這個資料槽。
- 起雨時間**一場雨只算一次**：`RainAnchor` 把第一次算出的時間存進 Storage，之後每次刷新都沿用，直到雨停滿 20 分鐘（約兩個 QPESUMS 報次）或冷卻的 90 分鐘到期才重算。每個地點分開記錄，關注列表中的多個城市不會互相覆蓋。若每次刷新都重取「現在 + 10 分鐘」，通知時間會跟著往後滑，系統可能永遠等不到那一刻。
- 過去一小時已經有明顯雨量時視為「正在下雨」，不會再造出起雨轉折，也就不會發送「即將降雨」通知。
- 原生通知的排定時機由 iOS 決定，背景更新被系統節流時可能延後；`Auto` 模式因此在 App 沒有更新時用排程補送。
- 通知文案由系統依語言產生，模組無法自訂。

## 空氣品質

臺灣的空氣品質由環境部發布，Apple 不提供，因此 `airQuality` 資料槽由模組自行補上：資料取自環境部環境資料開放平臺 `AQX_P_432`（空氣品質指標 AQI），以最近測站對應請求座標，需要會員 API key（`API.Environment.Token`）。

模組同時注入一份**自建量表**（`TW.AQI.<修訂版號>`），因為天氣 App 要靠量表才知道指標怎麼分級、各級什麼顏色。幾個容易踩到的細節：

- 漸層色標的 `location` 是**量表數值本身**（`0`／`50`／`100`／`150`／`200`／`300`／`500`），不是 0～1 的比例。天氣 App 是拿 AQI 數值直接在漸層上取色，寫成比例的話所有色標會擠在量表開頭，整條漸層塌成同一個顏色，指標就沒有顏色區分。
- 色標必須落在量表的 `range`（`[0, 500]`）之內，且與 `categories` 的六個等級色一致，否則同一個數值會在卡片與量表上顯示成兩種顏色。
- 改動任何顯示內容都要**遞增修訂版號**（`AirQualityScale.Revision`）。天氣 App 會用回應裡的 `version` 重新請求量表，版號不變就繼續用快取中的舊定義，改了也看不到。
- 量表提供 `zh-Hant-TW` 與 `en-US` 兩份，其餘語言回退到 `en-US`。

## 天氣警特報

Apple 對臺灣**完全不回** `weatherAlerts` 資料槽，所以沒有「把中央氣象署的警特報併進 Apple 既有預警」這回事——沒有目標可以併。模組因此改為**自行組出整個集合**：`WeatherAlerts.BuildCollection()` 直接產生 FlatBuffer 解碼後的形狀（`attributionUrl` 小寫、列舉為大寫常數、時間為 Unix 秒），補進根資料表的第 6 個 slot。

只有在**真的有生效中的警特報**時才會補上這個 slot。沒有警報時整個 slot 不會出現，與 Apple 原本的行為一致，也不會讓天氣 App 顯示一個空的預警區塊。

幾個容易踩到的細節：

- 列舉必須是**大寫常數**（`SEVERE`、`IMMEDIATE`、`MONITOR`）。傳小寫或未知字串給編碼器會靜默寫成 `NaN`，App 讀到的嚴重度就全部變成 0。
- 時間必須是 **Unix 秒**。把 REST 的 ISO 字串直接塞進去，預警會被當成 1970 年而立刻過期。
- 中央氣象署的 CAP 沒有 `significance` 欄位，模組依嚴重度推導（`severe`/`extreme` → `WARNING`、`moderate` → `ADVISORY`、`minor` → `STATEMENT`），否則前端沒有級別可以排序。
- 預警的 `id` 由「地點＋事件識別碼」算出穩定 UUID，同一筆警報每次刷新都是同一個 id，App 才不會重複跳出通知。

**代價**：天氣 App 每更新一次天氣，就會多打 1～3 個 CWA 開放資料請求（先查縣市警報現象，再抓對應的特報資料集）。這是即時反映警報狀態的必要成本，與目前天氣、逐時、每日預報每次更新都會各打一次的情況相同。

## 已知限制

- CWA 的警報是「警特報」，不是 Apple 的逐事件預警；同一事件會合併為一筆，並保留最嚴重或最精確的區域。
- 天氣 App 是否顯示警特報卡片、以及顯示成什麼樣子，仍由 iOS 決定；模組只負責把資料補齊。若 App 版本本身對臺灣不渲染這個區塊，補了資料也不會出現。
- 觀測站可能距離實際位置數十公里，目前天氣代表附近觀測站的觀測值，不是格點插值。
- 月相由本地朔望月週期推算，可能有約半天誤差。
- 風速會從 CWA 的 m/s 換算為 WeatherKit 的 km/h。
- 授權碼請勿提交到倉庫或公開分享；本倉庫的預設值為空字串。

## 訂閱與更新

模組與腳本都使用固定的 `releases/latest/download/` 連結，因此**訂閱一次即可**，之後發布新版本時 Surge 會自動更新，不需要重新安裝。

訂閱網址：

```text
https://github.com/zoeee1125/WeatherKit-CWA/releases/latest/download/iRingo.WeatherKit.sgmodule
```

在 Surge → 模組 → 新增 → 貼上網址，即會以訂閱形式安裝並自動檢查更新。若要手動更新，在模組頁下拉重新整理即可。

## 建置

本倉庫已把 Apple WeatherKit 的 FlatBuffers 綁定內嵌為本地套件 `packages/weatherkit-schema`，所有相依都來自公開 npm，因此不需要任何 GitHub Packages 憑證：

```bash
npm install
npm run build          # 產生 dist/request.bundle.js 與 dist/response.bundle.js
npm run build:args     # 產生 dist/iRingo.WeatherKit.sgmodule 等模組
```

推送 `vX.Y.Z` 標籤會觸發 GitHub Actions 建立 Release；`latest` 永遠指向最新的非預先發布版本，訂閱端因此會自動取得新內容。
